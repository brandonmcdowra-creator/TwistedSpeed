### C2) Writer’s-block coach — **required every run**
This lab is a **planner and a writer’s-block buster**, not a suggestion spam machine.

For **every field id** in DESIGN-LAB.html, set `FI_LAB_SEED.fieldCoach[fieldId]` (and `lab-state.json` → `fieldCoach`) to either:
- a string, or preferably
- `{ "text": "...", "stance": "solid" | "gap" | "optional" }`

UI shows: **“Grok’s thoughts on this topic”** plus stance badge (Looks solid / Worth a look / Optional).

#### Stance rules (critical — do not ignore)

| Stance | When | What to write |
|--------|------|----------------|
| **`solid`** | Pack/code/manifest **already answers** this field clearly | Affirm what’s already true in 1–2 sentences. **Do not invent new features or alternate directions.** Example: “You’re covered: kill=EXP, stun→cuff=recruit. No change needed unless you want a different fantasy.” |
| **`gap`** | Field is empty, vague, contradictory, or risky | One concrete question or angle to unblock. Still no laundry list of features. |
| **`optional`** | Nice-to-have / later | Short “park this” note — no pressure to iterate now. |

**Anti-patterns (forbidden):**
- Forcing “what if you also added…” when the design is already clear  
- Iterating for the sake of sounding smart  
- Treating every field as broken  
- Writing the same generic “make it fun” blurb on every field  

**Default bias:** if the game already implements something, prefer **`solid`** over **`gap`**. Only use `gap` when something is missing, unclear, or actively harmful.

#### Prefill answers when the pack already knows
If code/PROGRESS/manifest already answer a field, **prefill** `answers` (or document in seed) so the director isn’t blank-page’d:
- Put text into `FI_LAB_SEED.prefillAnswers[fieldId]` and merge into the lab if the user hasn’t typed that field yet (or inject via packSignals step).
- Optionally set `FI_LAB_SEED.fieldAnswered[fieldId]` to `"full"` or `"partial"` so XP can treat pack-backed answers as solid.

#### XP (UI behavior to preserve / implement)
- Each field has `xp: N` (importance). Verb / loop / combat / next milestone = highest.
- **Partial XP (~50%)** for a thin/short answer once they start typing.
- **Full XP** for a solid answer (or `stance: solid` + any real answer / `fieldAnswered: full`).
- Empty = 0 XP. Top bar = sum of partial+full credits.

On refresh: rewrite thoughts only if stance/content should change because the pack **drifted**; don’t churn solid fields into new suggestions.

### D) Top-of-lab AI summary — **required at the end of every run**
After pack signals + coach notes are written, **ask yourself** these two questions (do not ask the director):

1. **“What am I least confident about regarding the current state of this game?”**  
   Honest uncertainty: fun, scope, onboarding, combat feel, empty systems, stale docs vs code, etc. Be specific to *this* pack.

2. **“What is the user missing in their design based on real-world indie game success stories?”**  
   Ground in real patterns (e.g. complete loop before content sprawl, readable first session, one clear verb, retention via short sessions, vertical slice, shipping small). **Do not** invent random features; name a *gap vs proven practice* and why it matters. Keep it constructive, 2–5 sentences each.

Write both answers into:
- `window.FI_LAB_SEED.aiSummary` in `DESIGN-LAB.html`:
  ```js
  aiSummary: {
    leastConfident: "...",
    missingForIndieSuccess: "...",
    generatedAt: "YYYY-MM-DD" // or ISO date
  }
  ```
- Same object in `fi-design-lab/lab-state.json` → `aiSummary`

The lab UI must show this block **first** (above phase content) as direct feedback every time the director opens the form. If regenerating HTML, keep that placement.

Also put a short version of both answers in your chat reply to the director.
